## 0. 摘要

1. **结构上不缺"功能"，缺"层"。** 我们现在有 5 个面（surface）、36 个视图文件、3 个互斥工作视图，
   但**没有"面板层"的通用语义**：面板的宽/折叠/位置/可见性各写各的，**只有钢琴卷帘有 2 处可折叠**
   （`ShowNoteParams` / `ShowExpressions`），主工作台的两侧列是**硬编码 `264,*,296` 且不可拖**
   （`MainWindow.axaml:458`）。用户说的"太挤"是**这个缺层**的症状，不是某一个面板画得不好。
2. **好消息**：本轮 **W16 已开工**且方向与本文结论**一致**（`PanelSplitter` + `PanelSlot` +
   `PanelLayoutPreferences`，未提交 WIP）。本文的价值是把 W16 从"三面板可拖"提升为
   **三级（视图/面板/子面板）× 五规则（可折叠/可调宽/可重置/状态持久/布局守卫）的成文契约**，
   并补上 W16 尚未覆盖的两级与两个入口（重置布局、键盘可达）。
3. **最贵的缺失是工程格式**：`.ustxp` 与上游**双向往返会静默丢数据**，且上游新版存的工程我们**直接抛错打不开**
   （`ustxp-format-audit §0/P1`，【实测】352,551 B → 2,509 B）。这是唯一"用户数据会没"的类别，
   **应排在所有体验类工作之前**。
4. **第二贵的是"没有命令层"**：菜单项是 XAML 硬编码 + 快捷键是 `OnKeyDown` 里一个 70 行 `switch`
   （`MainWindow.axaml.cs:1479-1548`）。同一张快捷键表**写了两遍**（`InputGesture=` 供显示、`switch` 供行为），
   于是「快捷键总览 / 自定义 / 命令面板 / 可发现性」四件事**全部做不了**。
5. **"可测量验收"已经是我们的资产**：W7 的 `AudioMeasure`（自带 FFT/Goertzel/LUFS 近似/RT60/相关度）
   + 8 个测量测试文件已能给出**数值回归**。它应该从"音频专用夹具"升级为**产品级能力**
   （未来的性能预算、听感回归、上游摘取的数值对照都靠它）。

### 1.6 工程与文件格式（`.ustxp`）

结论摘自 `ustxp-format-audit.md`（**未改动，仅引用**）：

- `.ustxp` = **上游 `.ustx` 的那份 YAML** + `ustxp_version` + 每轨 `vst_slots`（VST 状态是**一行 base64**）。
- **P1（高，唯一"丢数据"级）**【实测】：Plus → 上游能打开但保存时**静默丢掉整条 VST 链**
  （样本 352,551 B → 2,509 B）；上游写 `ustx_version: 0.10` > 我们的 `0.9` ⇒ **我们再也打不开**（抛 `Project file is newer than software`）。
  上游 `expression_graphs` / `default_expression_graphs` / `expression_graph` / `masked_curves` 我们**静默忽略并写掉**。
- **P2–P7**：Plus 键与上游键平铺无命名空间（上游已引入 `UnknownKey` 诊断，将来会打架）；
  迁移阶梯**两份拷贝** + `RunPlusMigrations` 空壳 + `Ustx.Save/Load` 死代码；
  大对象内联（1 MB 状态 → 1.4 MB 文件、单行 1.4 M 字符）；每轨恒写空集合与 `eq_bypassed` 冗余键；
  **素材无清单/无打包**（外部音频写成 `..\MusicLib\x.wav`，换机即失效）。
- 推荐路线：**C（止血）→ 视用户诉求再决定 A（`plus:` 段）/ A+（侧车）/ B（zip 容器）**；
  5 个待拍板问题见该文档 §5（本文不重复，仅在 §5 说明它与产品结构的关系）。

### 1.9 本地化

- 载体：`OpenUtau/Strings/Strings.*.axaml`，**共 19 个语言文件 + `unhandled_strings.json`**。
- **EN 唯一键 1022 / zh-CN 唯一键 1022，双向差集 0**（`checks.ps1` 已把这条固化为集成检查）。
- **语言陈旧度【实测】**：除 EN/zh-CN 外的 **17 个语言只有 541–562 键**（ja-JP 562，其余 541）⇒ **约 47% 缺失**。
  缺的键在运行时**回退到 EN**（`ThemeManager.TryGetString` → 资源字典），所以不会崩，但会**中英混排**。
- **没有**：缺失键检测（CI 级）、占位符/复数的规范化校验、翻译贡献流程、语言完整度提示。
- 结构上：两文件都有**标记区块**（如 `<!-- fx-ui: effects rack -->`）用于并行作业合并。

## 3. UI 密度专题（用户痛点："太挤"）

### 3.1 挤在哪：证据

#### (a) 两个固定侧列吃掉近一半窗宽（最容易复现的一条）

- `MainWindow.axaml:458`：`MainLayout ColumnDefinitions="264,*,296"` —— **两列都是固定像素，且没有 `GridSplitter`**。
- 窗口声明 `Width=1440`、`MinWidth=300`（`:13`）⇒ **只有 300px 时，固定侧列 560 已经比窗口还宽**。
- 【实测】截图 `mx-01-workspace.png` 是 **1226×699** 的真机窗口：侧列占 `560/1226 = 45.7%`，
  中央编排区只剩约 600px（再扣掉 `*,8` 的滚动条列）。
- 【实测】素材库那 296px 里，当"未找到歌手"时（`mx-01`）**几乎全空**——固定宽度与内容需求完全脱钩。

#### (b) 混音台：一条 96 的通道条 + 两个"必须占着"的固定区

- `MixerControl.axaml:48`：`ColumnDefinitions="1,280"` ⇒ **链面板恒占 280**，与"是否有链路内容"无关。
- 主输出条固定宽 **160**（`spec-digest §3`）。
- 【实测】`mx-42-mixer.png`（1226 宽，混音台 overlay 只铺前两列并让出素材库 296）：
  真实内容 = 1 条 96 通道条 + 主 160 ⇒ **约 256px 的内容**，却要占满 ~880px 的区域，
  中间与链面板内部**大片空**。⇒ 这条痛点本质不是"太挤"而是**"固定宽度不随内容和任务变化"**。

#### (c) 卷帘：右栏 400 固定 + 表达式 150 固定

- `NotePropertiesControl.axaml:6` **Width=400**；`PianoRoll.axaml:23` 表达式行高 **150**（Min/Max 可调 ⇒ 唯一"半可调"处）。
- 行 `24,24,24,*,Auto,150,4` + 列 `60,*,24,Auto`：**只有 1 个星号列**，
  在 1200 设计宽下音符区 ≈ `1200-60-24-400 = 716`；窗口更窄时**只有音符区挨压**，右栏不动。
- 【文档确证 `spec-digest §11`】设计稿的竖向预算是"零冗余"（`900-56-32=812`；通道条内容 702 + 9×gap 54 + spacer 8）
  ⇒ **稿本身就没有给"更小的屏幕"留余量**，实现照搬必然挤。

#### (d) 层级过深的地方（找东西的代价）

- 功能入口：**品牌按钮 → 一级菜单 → 二级 → 三级**（导出音频 → 渲染 / WAV / 混缩；导出工程 → UST/MIDI/DS）。
- 素材库第 4 页签「效果器」：`顶栏胶囊 → 混音台 → 素材库 → 效果器 → 拖到链面板`（D9 主路径，**至今未验证**）。
- 混音台链面板：`视图胶囊 → 混音台 → 选中轨道 → 右侧链面板 → 双击行`。
- 卷帘属性：`视图胶囊 → 钢琴卷帘 → 选中音符 → 右栏 400px`（`ShowNoteParams` 才可见）。

#### (e) 窗口级：状态条承诺 6 项、实际 2 项

`spec-digest §4` 要求 `Audio Info · Latency · Voices · CPU · Disk`，但 `§6` 明确"没有数据源就不许编数"；
【实测】`mx-01/mx-42` 状态条只有左端一个圆点 + 右端版本号 ⇒ **32px 高度基本被浪费**，
而它同时是"将来放性能指标最多的地方"（接 M16）。

### 3.2 目标信息架构与规则

**三级定义**（把 §1.2 的树按"谁拥有宽度"重新分层）：

| 级 | 定义 | 举例 |
|---|---|---|
| **L1 视图（View）** | 顶栏胶囊切换的整屏工作面；互斥显示；拥有自己的面板组合 | 工作台 / 钢琴卷帘 / 混音台 |
| **L2 面板（Panel）** | 视图内**有标题、可独立调宽或折叠**的矩形区域 | 轨头列 / 素材库列 / 编排区 / 卷帘右栏 / 表达式栏 / 混音链面板 |
| **L3 子面板（Sub-panel）** | 面板内部可折叠的**分组**，不拥有宽度（继承父），通常纵向堆叠 | 素材库四个页签 / 轨头卡片内的 M·S·fx 组 / 链面板的链段 / 属性栏的 4 个 `Expander` |

**五规则（每级都要满足，L1 的部分规则退化为"整视图"语义）**：

| 规则 | L1 视图 | L2 面板 | L3 子面板 |
|---|---|---|---|
| **① 可折叠** | 通过胶囊切换（等价折叠）；分离按钮 | **必须有**：标题栏折叠按钮 + 折叠后**列宽为 0**（不留窄条/不留白） | **必须有**：分组头可折叠；折叠态只留标题行 |
| **② 可调宽** | 不适用 | **必须有**：`PanelSplitter` 拖拽 + **双击复位默认** | 继承父宽；纵向可调高（如表达式栏） |
| **③ 可重置** | — | 双击分隔条复位**该面板**；菜单「重置布局」复位**全部面板**（见 ④） | 折叠态随父面板持久 |
| **④ 状态持久** | 当前视图 + 分离偏好 | 宽度与折叠态写 `Preferences.PanelLayout`（**单一存储，不新增平行来源**） | 折叠态同上（按面板 key 命名空间） |
| **⑤ 默认布局守卫** | 视图切换**不让布局抖动**（已是现状：只翻 `IsVisible`） | **中央列 `MinWidth`（建议 320）+ 每面板 `Min/Max`**；任何拖拽/窄窗都必须夹紧，**不许把主编辑区挤没** | 折叠不得改变兄弟面板宽度 |

**必须补齐的三个契约细节**（W16 WIP 尚未覆盖，建议直接纳入其验收）：

1. **布局重置入口**：`PanelSlot.Reset()` 已存在【代码确证 W16 WIP】，但需要**可见入口**
   （菜单「视图 → 重置布局」+ 可选快捷键）。否则用户拖坏了只能删 `prefs.json`。
2. **键盘可达**：`PanelSplitter` 目前只有"拖拽 + 双击复位"【代码确证】⇒ 需补
   `←/→` 步进、`Home` 回默认、`Tab` 可聚焦 + 焦点环（与今年 FX 机架旋钮/开关同一套无障碍要求）。
3. **窄窗行为**：`MinWidth=300` 与"两侧面板 + 中央 320"矛盾。建议**窗口 `MinWidth` 提到
   `左侧 Min + 右 Min + 320`（约 900）**，或定义"窄窗自动折叠优先级"（先折素材库、再折轨头，并**记住**是"自动"而非用户选择）。
   → 这是 §5 的待拍板问题之一。

**另需一条"密度档位"规则（M17）**：同一套面板应有 `comfortable / compact` 两档，
只改三类令牌（行高、内边距、字号），**不改结构**；档位存 prefs。这样"小屏挤"与"高分屏空"用同一机制解决。

### 3.3 DAW / IDE 惯例参考：该抄什么、不该抄什么

| 参考 | 它的做法 | **该抄** | **不该抄** |
|---|---|---|---|
| **Ableton Live** | 底部/右侧信息面板可折叠；**Session/Arrangement 两个视图整屏切换** | **整视图互斥切换 + 折叠面板**（正是我们已有/在做） | 双视图各自独立状态机（我们 3 视图共用一套 chrome，简单且够用） |
| **Reaper** | 极致的 docking：任意面板可停靠/浮动/重排/Docker 容器；布局可命名保存 | **"双击分隔条复位 + 布局持久"**这类低成本习惯；**面板宽度记忆** | 全量 docking 引擎（自由停靠 = 布局状态爆炸、每控件都要适配宿主；见 M08 建议不做） |
| **Bitwig** | 右侧信息面板 + 底部编辑器；**面板内容随选择自动切换** | **"上下文面板"**：面板内容跟选择走（我们的链面板已经是这个模式） | 一切皆可分离窗口（我们已有"视图分离"够用） |
| **VS Code** | 活动栏/侧栏/面板三级；**命令面板 Ctrl+Shift+P**；快捷键完全可自定义 + 冲突检测；布局可持久、有"重置视图" | **命令面板（M10）+ 快捷键总览/自定义（M11）+ 重置布局入口** —— 这三条**性价比最高、直接抄** | 扩展宿主/沙箱进程模型（我们要的是插件隔离，但不必做成 VS Code 那种扩展 API 规模） |
| **Photoshop** | 面板自由停靠 + 工作区预设（Essentials/Painting…） | **命名工作区预设**（M07）：我们可用"编曲 / 调声 / 混音"三套 | 自由浮动面板 + 面板组（对单人音乐工具是负担） |

**结论**：**不做 docking（M08 保持 P3）**，改走"**固定分区 + L2 可调宽/可折叠 + L3 分组折叠 + 整视图分离 + 命名预设**"的替代路线。
成本差一个数量级（M05+M06+M07 ≈ 6–12 人日 vs M08 ≈ 15–30 人日），而覆盖 90% 的实际诉求。

## 5. 需用户拍板的问题（5 条，每条带默认建议）

| # | 问题 | 默认建议 | 为什么必须你拍板 |
|---|---|---|---|
| **Q1** | **多工程形态**：标签页（同窗口）/ 独立第二窗口 / 只做"会话恢复不做多工程"？ | **先做会话恢复**（S3-a，3–5 人日）；标签页等出现真实"同时开两个工程"的需求再做 | 三者的架构代价差 3–5 倍；标签页会牵动 `DocManager` 单例、播放器单例、面板状态归属 |
| **Q2** | **布局系统的目标形态**：接受"固定分区 + 面板调宽/折叠 + 命名预设"（**不做 docking**）？窄窗时是否允许**自动折叠**面板（并记住这是自动行为）？ | **接受不做 docking**；窗口 `MinWidth` 提到约 900；窄窗**自动折叠素材库→轨头**并标记为自动 | docking 是全量重写（15–30 人日）且与"面板内容跟选择走"的现有模式冲突；自动折叠涉及"用户的布局是否被系统改动"的心理预期 |
| **Q3** | **是否投入"命令层"**（它是命令面板、快捷键自定义、脚本化的共同前置）？ | **投**（5–8 人日）；其中"快捷键只读总览 + 冲突检测"可**先做**（1–2 人日，立刻可用） | 这是本文件里"性价比最高的结构性投资"，但会改动菜单/快捷键两大入口，需要你认可回归窗口 |
| **Q4** | **18 个语言的收缩**：非 EN/zh 的 17 个语言只有 ~47% 键，是**补齐**、**标记为"社区翻译（不保证完整）"**、还是**只保留 EN/zh + ja**？ | **标记 + 检查**：加缺失键检测（CI），界面按完整度显示提示；**不删除**任何语言文件 | 涉及用户感知（有人只用德语界面）与社区贡献意愿；纯技术侧无法决定 |
| **Q5** | **遥测口径**：要不要"本地性能面板"（只看不外发）？是否允许**可选、默认关**的匿名崩溃上报？ | **只做本地性能面板**（M16），**不做任何外发上报** | "外发"是隐私/信任问题，必须你定；本地面板无风险，可直接进 S2-a |
