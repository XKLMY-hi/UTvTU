## 0. 上一轮两处问题的核实结论（先清账）

| 问题 | 事实（可复算证据） | 处置 |
|---|---|---|
| **背景"透着主窗内容"** | 对 `w36-light.png` / `w36-dark.png` 做像素采样：启动器空白区 45×55 网格 → **不同颜色数 = 1**；窗口最外缘 x=1200…1224 逐点 = `FF141218` ×4 行，**alpha = FF**。⇒ 欢迎面**本身是全实色**，不是半透明。图上那些"轨头/状态条/别的应用文字"来自**截图时应用窗口未完全置顶**（另一窗口覆盖了捕获矩形的一部分）——截图方法问题，**不是产品缺陷** | 新实现后统一**先 `SetForegroundWindow` 再截**，并在报告里附"空白区单一色"像素校验数（同一脚本可复算） |

## 1. 候选 A ——「继续工作」单栏列表（**推荐**）

```
┌─ UTvTU  13·Medium     ·  音源 6 · 引擎 2 · v0.1.568       ← 20px 标记 + 一行环境摘要（真实数据）
│ ⟳ 上次未能正常关闭的工程「xxx」 → 恢复                    ← 有恢复项时置顶（error-container）
│
│ 最近工程                                   打开其它工程…  ← 区块标题 13 + 右侧安静链接
│ ├ Neon Horizon.ustx          USTX · D:\songs\…   2 小时前
│ ├ Rin & Len Duet.ustxp       USTXP · E:\…        昨天
│ └ …（行高 44，名称 14/Medium；meta 11 右对齐同排可读）
│
│ [＋ 新建工程]  [打开…]  [导入音频]  [模板 ▾]               ← 一行紧凑按钮（高 32–36），仅"新建"为 primary
│
│ 文档 · 发布日志 · DiffSinger · Kasane Teto 官网            ← 11px 安静内联链接
└
```
- **信息优先级**：继续工作 > 崩溃恢复 > 新建/打开/导入/模板 > 环境摘要与链接。
- **取舍**：放弃"品牌感"与两栏；换成单栏后列表宽度翻倍 ⇒ 目录与时间能同排，扫读成本最低。
- **为什么更适合我们**：反复打开时用户 90% 是来"继续上次"，**列表就是主角**，其余都要让路；
  一个 20px 标记足够回答"我在哪个应用"。恢复条置顶是因为它是当下最该点的东西。
- **几何元素**：**不用波形**（它不挣位置）。几何感由 4px 网格、行高节奏、1px 分隔线承担。

## 2. 候选 B ——「工作台摘录」主列表 + 右侧 240 状态栏

```
┌ 最近工程 ─────────────────────────────┬ 环境 ─────────┐
│ [＋新建] [打开] [导入] [模板▾]         │ 音源 6（列名）│
│ 行…（同 A 的列表，但更宽）             │ 引擎 2        │
│                                       │ 版本 v0.1.…   │
│                                       │ 文档/发布/…   │
└───────────────────────────────────────┴───────────────┘
```
- **信息优先级**：继续 > 动作 > 常驻环境状态。
- **取舍**：环境状态常驻可见（音源/引擎是 UTAU 用户常关心的）；代价是右栏在 1000px 宽时会被压窄。
- **风险（我必须说）**：**两栏构图离上一轮被否掉的稿子结构最近**，很容易再次滑向"品牌栏 + 内容区"。
  若选 B，右栏必须严格限定为**状态信息**（无 logo 英雄位、无标语、无装饰块）。

## 3. 候选 C ——「命令优先」搜索式启动器（键盘流）

```
┌ 搜索或执行命令…（⌘K）               ← 输入即过滤：最近工程 + 命令（复用 W28 命令注册表）
│ ▸ 继续 Neon Horizon.ustx
│ ▸ 新建工程            Ctrl+N
│ ▸ 打开…               Ctrl+O
│ 快捷键提示：↑↓ 选择 · Enter 执行 · Esc 关闭
```
- **信息优先级**：意图（我要做什么）> 列表 > 一切装饰。
- **取舍**：键盘效率与可扩展性最高；但鼠标用户多一次输入成本，且**依赖尚不存在的命令面板能力**。
- **不选它的理由（本轮）**：搜索框是**新功能**（属产品设计 M23 命令面板），塞进"欢迎页重设计"会越界、
  也会同步放大风险；它是 A 的**下一卡增量**，不是本卡的替代方案。

---

## 4. 推荐：**候选 A**

1. 最贴合"反复打开 + 信息优先 + 零营销"，也最彻底地摆脱稿子的两栏构图（**结构性照搬 = 0**）；
2. 实现量与风险最小：单栏 + 列表 + 一行按钮，全部沿用上一轮已验证的技术底座
   （Button 语义 / Tab 序 / Space·Enter / 焦点环零位移 / ScrollViewer 防溢出 / 不用 ListBox / 压 `MinHeight`·`Margin`）；
3. 天然容纳"恢复条置顶"与"4 个动作恒可见"两条修正；
4. 不做 B 的右栏（避免构图回退风险），不做 C 的搜索框（避免越界到 M23）。

**若用户偏好"环境状态常驻"**，B 是唯一合理的替代；C 建议单独开卡。
