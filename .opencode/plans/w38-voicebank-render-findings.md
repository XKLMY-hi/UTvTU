# W38 声库渲染 / 路径 / 许可 —— 可复用知识（实测留档）

> 来源：W38「欢迎页一小节真实演唱」做候选 a（真声库渲染）时的实测过程。
> 目的：把**三个发现**留痕，避免后人重复踩坑或据错误结论改产品代码。
> 相关实现：`OpenUtau.Test/Tools/WelcomeWaveformGenerator.cs`、资产目录 `.opencode/design/welcome-waveform/`。

## 1. 「声库声明了 presamp ⇒ 通用音素化路径走不通」——**被实测证伪**

最初假设：声库在 `character.yaml` 里声明 `default_phonemizer`（如 `JapanesePresampPhonemizer`）后，
生成器复用的 `ClassicRenderSetup`（通用路径）就拿不到「音素 → oto」映射 ⇒ 短语为空 ⇒ 超时。

**实测结果与假设相反**——本机 5 个声库逐个试跑（tone 60、720 ticks ≈ 0.75 s、经典链）：

| 声库 | 是否声明 phonemizer | 结果 | 失败签名 |
|---|---|---|---|
| `足立レイver3.5.0` | **声明 presamp** | ✅ **成功** | — |
| `uta`（唄音ウタ/Defoko） | 未声明 | ❌ TimeoutException | `PhonemesUpToDate=True, phonemes=1, phrases=0`（20 s） |
| `高松灯_Classic_Ver1.0.0` | 未声明 | ❌ TimeoutException | 同上 |
| `回音ドバオ v1.7` | 未声明 | ❌ TimeoutException | 同上 |
| `桃音モモOU统合` | 未声明 | ❌ TimeoutException | 同上 |

⇒ **唯一成功的是"声明了 presamp 的那个"**，四个未声明的全失败。

> ⚠ **真正判别因素未确定，勿据此推断**。怀疑方向（**均未验证**）：
> ① `oto.ini` 的目录层级与别名集合；② 是否依赖 `.frq`；③ `character.txt` 与 `character.yaml`
> 的取舍（`DummyVoicebank.Load` 用 `character.txt` 作为 `Voicebank.File`）。
>
> ⚠ 无论原因如何，这都属于**测试夹具构造方式**的限制，**不是产品缺陷**：应用加载声库走的是
> 插件工厂（按 `character.yaml` 的 `default_phonemizer` 构造），产品里这些声库能正常渲染。
> **不要把它当 bug 去改产品代码。**

## 2. 「`桃音モモOU统合` 没有 `character.yaml`」——**是我自己吓自己，不是夹具 bug**

- 当时的判断来自：手敲路径字面量 `...\Singers\桃音モモOU统合\character.yaml` + `Test-Path` ⇒ 假。
- 实测复核：该目录 **12 个声库全部同时存在 `character.yaml` 与 `character.txt`**，含 `桃音モモOU统合`。
- 根因：**手敲的非 ASCII 目录名字面量未与磁盘上的名字逐字节相同**（控制台对日文/中文目录名会乱码，
  复制粘贴时极易串码）。
- 结论：生成器的 `FindVoicebank()` 用 `Directory.GetDirectories()` 取**真实名**，命名方式是对的；
  **不要去查夹具**。以后核对非 ASCII 路径，一律**先 `Get-ChildItem` 再拼接**，不要手敲。

## 3. 第三方资产的**许可调查方法**（照此办）

做候选 a 时形成的方法（可复用）：

1. **找条款文件**：声库根目录的 `readme.txt` / `character.txt` / `利用規約等\*.txt` / `character.yaml`。
   日文老声库多为 **Shift-JIS**：`[System.IO.File]::ReadAllText(path, [System.Text.Encoding]::GetEncoding(932))`
   —— 直接用 UTF-8 读会全是乱码，导致误判"没有条款"。
2. **逐条引用 + 出处**（不要转述），并且**分清两件不同的事**：
   - **「使用该资产产出的作品/衍生图形」**是否允许（我们产出的是波形图形 = 作品/衍生图形）；
   - **「再分发资产本体」**是否允许（我们并不做）。
3. **把保留条款单独拎出来**（尤其"法人商用需另行联系""禁止再配布"这类），因为它决定"能否随包"。
4. **优先自研**：只要能用零顾虑的自研资产替代，就不背第三方尾巴——即使条款看起来允许。

**范例（`足立レイver3.5.0`，本机实测读出，出处 `利用規約等\足立レイのガイドライン.txt`）**

- 「**音源の再配布は可能です。プログラムや機器に組み込んでの使用も可能です。**」⇒ 再配布 + 嵌入程序/设备均被允许。
- 「二次創作等については、同人活動の範囲内においては、基本的に**有償・無償を問わず自由**に…」
- 「**法人による商用利用は、別途ご連絡ください。**」⇒ **唯一的保留条款**。
- 出处二 `readme.txt`：「このライブラリには**人の声は含まれていません**。sin波合成による母音を元に…」
  ⇒ 该声库**本身也是合成音源**（不含人声）。

**反例（`uta`）**：`readme.txt` **没有任何许可条款**（关键词 grep 零命中）⇒ 即便它能渲染，
也**不能**仅凭本地文件判断可否随包，需要外部（官网/作者）确认 ⇒ 该路线不值得投入。

## 4. W38 的最终裁决与其依据（供后续卡片引用）

- **随包资产用候选 b（自研合成 /a/：共振峰 F1 800 / F2 1200 / F3 2800 + 谐波 + 5.5 Hz 颤音 + ADSR）**；
  **候选 a（足立レイ真声库渲染）只作本地对比参考，不随包**。
- 依据不只是许可，更硬的是**观感**：a 是**平顶矩形**（该声库是 sin 合成母音 + worldline 平直延音，
  几乎无自然起伏）⇒ 作为"一小节真实演唱"的缩略，说服力反而低于几何装饰；b 有清晰的 ADSR
  轮廓（渐强 → 带颤音起伏的中段 → 自然衰减尾）⇒ 读得出"唱出来的一小节"。
- 复用价值：`b` 的生成器（含 112 点包络、绝对值/双极性、共用分母归一化）可作为同类"真实数据形状"
  装饰件的模板；a 的试跑路径与许可调查结论可直接引用。
