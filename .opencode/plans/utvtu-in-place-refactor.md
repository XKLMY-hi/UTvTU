## 1. 已确认的方向

- 定位：**人声制作工作站**，覆盖歌声编辑、合成、混音与交付的完整流程。
- 方式：在现有 UTvTU 上渐进重构，上游 OpenUTAU 作为设计与行为参考。
- 平台：当前仅验证 Windows，不扩展移动端或其它桌面平台。
- 产品原则：歌声制作是中心；混音与交付服务于这条工作流。通用 DAW 功能按实际需求逐项评估。
- 前端需要重新梳理信息架构、交互状态、模块职责和样式归属。界面重构应落实这些边界。
- 前后端共同推进：每条工作流同时交付交互状态与应用/核心边界，前端审查和验收从第一批开始。

前端源码审查见 [审查报告](<G:/xklmy文件夹/vibe coding/UTvTU/.opencode/plans/frontend-review-2026-10-11.md>)。
桌面程序的“前后端”指 UI/交互与应用/核心运行时的职责，本路线不引入 Web 服务。

## 3. 上游如何作为参考

| 上游已核查的实现 | UTvTU 可借鉴的原则 | 采用前必须验证的差异 |
|---|---|---|
| `Pipeline/Identities.cs`、`Pipeline/Snapshots.cs` | 工程修订号、修改影响范围、后台使用快照 | 编辑、撤销和实时调参是否都能生成一致的修订；快照是否覆盖所需输入 |
| `Pipeline/PhraseSourceBuilder.cs` | 后台构建乐句，旧请求退出时不能覆盖新结果 | 取消、工程切换、歌手释放、缓存失效 |
| `SignalChain/MixPlanner.cs`、`SampleSlot.cs` | 文档缓存与播放会话分开；音频回调消费已发布的数据 | UTvTU 的 VST、实时效果和延迟销毁安全点 |
| `Render/RenderView.cs` | 渲染结果通过只读投影更新界面，并合并通知 | 当前仍依赖 PlaybackManager 单例，这一耦合应单独处理 |
| `RenderEngine.RenderMixdown` 的 planner 参数 | 导出使用独立计划器，避免污染播放状态 | 播放与导出结果、节拍器、范围导出和插件状态 |
| 独立 `OpenUtau.UiTest` 工程 | 进程级应用初始化与其它测试隔离 | UTvTU 当前测试宿主、全局状态和真机验收方式 |

上游也保留了 DocManager、DocumentSnapshotStore、RenderView 等单例。评价标准应是边界是否明确、
行为是否正确、生命周期是否完整、能否独立验证；具体实现按这四点取舍。

## 4. 目标职责与依赖

先确立逻辑边界，按实际需要拆程序集，避免一次新增大量空工程。

| 模块 | 负责 | 应通过明确接口交接的工作 |
|---|---|---|
| 应用壳与工作区宿主 | 窗口、视图导航、面板布局、分离与收回 | 保存、导出、工程编辑、音频设备选择 |
| 前端功能模块 | 编排、歌声编辑、混音、素材库、偏好设置的交互与呈现 | 共享工程修改、后台作业、插件资源管理 |
| 应用操作与工程会话 | 命令路由、工程修改、撤销、脏状态、作业调度、会话关闭 | 窗口控件、DSP、文件格式编码 |
| 工程数据与文件服务 | 项目数据、兼容读写、保存结果、恢复与迁移 | 实时插件实例、播放状态、视图布局 |
| 合成与缓存 | 音素化、乐句构建、合成器适配、缓存、失效与结果发布 | 用户导航、实时混音参数、输出设备 |
| 音频与插件运行时 | 运输控制、信号链、效果、输出、导出消费、插件生命周期 | UI 控件和实时读取可变工程对象 |

目标调用关系：视图 → 功能 ViewModel → 应用操作/会话 → 数据或运行服务。
组合入口负责创建实例和连接接口；回调、订阅、计时器、任务及原生资源必须有明确拥有者。

过渡期可由适配器封装现有 DocManager、PlaybackManager 和 RenderEngine。
每次替换一个调用入口并迁移全部调用者，验收后删除被替代路径，防止永久形成两套状态来源。

## 5. 建议实施顺序：按工作流共同交付

### 切片 0：前后端共同基线与交互契约

核对当前基线能否构建、运行；测试数字取实际输出。选择固定工程覆盖保存、重开、撤销、
歌手切换、试听、导出和 VST 状态恢复。前端同步梳理导航、焦点、加载/失败/未保存状态，
形成工作区状态图与模块边界。回滚前的高风险修复逐项复现后采用。
产品功能、缺陷修复、依赖升级和结构调整分别提交。

### 切片 1：混音修改 → 保存、取消与工程切换

前端审查发现推子脏状态遗漏、M/S 命令捕获错误旧值、机架预览与保存/取消冲突、
旧效果窗口污染新工程状态（F01–F04）。建议以这条工作流作为首批实施范围。

前端：定义推子手势与撤销反馈、机架预览/取消契约、跨视图同步和保存状态呈现。
后端：建立统一修改事务、工程身份和修订记录；迁移轨道头与混音台全部对应入口，
通知接收只更新显示。拖动实时发布参数，结束时合并为一次撤销记录；
混音修改避免不必要的歌声重渲染。VST 原生 GUI 参数的撤销单独验证。

保存针对明确修订：收集状态 → 序列化 → 临时文件写入 → 原子替换 → 成功后更新保存点。
保存期间产生新修改时仍显示未保存。失败、自动保存、格式导出分别定义结果；
预览参与保存与取消的规则在实现前评审。旧工程兼容与用户数据目录保持既有约定。

验收：只改混音后退出/自动保存正常；保存重开一致；M/S 撤销重做正确；
预览中保存再取消有明确结果；旧窗口回调不得改变新工程。

### 切片 2：打开工程 → 工作区导航、分离与关闭

前端：整理可用入口、欢迎/偏好覆盖层、选中片段、分离窗口、焦点返回和错误反馈；
修复偏好页实例订阅归属（F05），明确钢琴卷帘进入条件（F06）。
后端：提取工程文件操作与会话关闭服务，命令从显式上下文获取服务，
窗口提供文件选择与确认；旧会话的任务/回调/订阅必须有明确收尾。

现有 CommandDefinition 持有 Action<MainWindow>，仍需解耦；
保留已工作的注册表、快捷键 CanExecute 检查、ViewSwitcherPolicy 与 DetachAndFlush 保护。
工作区宿主管导航和分离/收回，区分临时隐藏、重挂与永久销毁。

验收：菜单/快捷键一致；取消或失败保存不退出；入口不可用有解释；
反复开关设置不积累旧实例；分离/回收不重复订阅或破坏焦点。

### 切片 3：歌声编辑 → 合成与试听

前端：手势即时反馈、选择/滚动和可见区域绘制、合成进度/失败/过期结果状态。
后端：在现有 RenderEngine 门面下评估上游校验合并、影响范围、快照、乐句构建与缓存。
一次替换一种机制，前端反馈不等待重复重计算；取消与结果发布绑定工程及修订。

验收：拖动一次有一条可用撤销记录；最终编辑与合成对应；
旧任务不回写新工程；用固定工程记录响应/校验耗时，依据采样决定性能工作。

### 切片 4：混音试听 → 导出交付

前端：导出范围、进度、取消/失败反馈，以及试听与交付结果对照。
后端：逐项处理播放与导出计划隔离、效果/VST 状态、Waited 时间语义、
音频块发布和插件销毁安全点。音频回调不执行文件 IO 或模型推理。

验收：试听与导出时序/效果正确；插件增删、seek、停止、工程切换和同时导出安全。

### 贯穿每个切片：前端体验、样式与绑定

每个模块同时处理信息层级、键盘可达性、状态反馈、样式归属和类型化绑定，
不把前端审查或验收放在最后。职责拆分与大面积视觉修改分批提交。
几何与令牌以用户 HTML 为准，图像用于观感参考；现有设计的取舍需具体设计评审。
按用户最新授权直接推进，不再等待逐批审批；每批交付可实机检查的结果与明确验证范围。
测试验证行为与呈现，保留必要的设计源一致性契约。

## 6. 第一批评审与验收要求

- 首批已落实“混音修改与保存契约”：命令写模型、手势合并撤销、实时预览参与保存、旧会话禁止写入。
- 同步梳理工作区导航状态与前端模块边界；每个切片列出前端和后端各自交付及共同验收。
- 任务写明目标文件、依赖、行为约束、替换入口和验收方式；同一文件只有一个写入者。
- 每完成一个通过验收的步骤立即中文原子提交。阶段结果可预览、可回退，避免积累长期 WIP。
- 工程往返、音频时序、撤销、失败保存和资源释放必须用行为证据验证。
- 重构进度以职责迁移和旧路径删除衡量，新增文件数和代码行数不作为目标。
